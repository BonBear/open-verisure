- [2026-11-16] [TOOLS/OTII]: The Arc can be scripted without an Otii license by running otii_core yourself on \\.\pipe\com.qoitech.otii3 (protocol in C:\repo\OpenOtii\docs\protocol.md): start `otii_core --init restore --project <new empty dir>\data --listen-socket <pipe>` and connect at once (`init client persist`, the core crashes if no session arrives); `device add <hw_id>`, `measurement add/arm`, `recording start/stop`; read back with `viewport add/width/fixed` (channel_stats, minmax_view_binary). - [2026-11-22] [TOOLS/OTII_POWER_CLI]: To turn Otii Arc ON from a script: launch `otii_core.exe --init restore --project <parent>\data --listen-socket \\.\pipe\com.qoitech.otii3` where `<parent>\data` does NOT exist yet (only `<parent>` exists; otherwise `otii_core` errors with `missing versions dir`), send `init client persist`, read the Arc UUID from the `devices` JSON message, and send `device <id> set_float mainvolt <V>`, `set_float maxcur <A>`, `set_bool main on`. CRITICAL for turning OFF: forcefully killing `otii_core.exe` leaves the Arc hardware power ON! Always explicitly send `device <id> set_bool main off`, wait ~1 s, and only then terminate `otii_core.exe` (and verify 0 `otii` processes). Also note `openotii.exe power` turns main OFF immediately on exit (`~Client()` fail-safe).

- [2026-11-25] [SIREN/BSL_V110_RAM_0400]: On BSL v1.10 (MSP430F149 Rev S) RAM 0x0400..0x05FF is not safe for the flash-writer data buffer: written bytes read back corrupted deterministically (e.g. chunk 0x2300 bytes 74..75), which caused the sporadic Verification mismatch / stub status 0x0004 failures.
