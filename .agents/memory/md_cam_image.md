# Memory: MD_CAM Image Pipeline

## 🖼️ Camera Image Pipeline (OV7955, PPI, JPEG, delta)
- [2026-11-14] [MD_CAM/PLL_ROOT_CAUSE]: The factory boot stream's init block sets PLL_CTL 0x1400 (VCO 240 MHz from CLKIN 24 MHz), PLL_DIV 2 (CCLK 240, SCLK 120 MHz), VR_CTL 0x70B0 and EBIU SDRAM. Without it the ROM leaves SCLK at 36 MHz and the PPI (max SCLK/2) sampled the pixel clock wrongly: this was the root cause of the 1.5x line length and broken colour seen 2026-11-12..14 (an earlier "same PLL" reading was taken after the original had booted). snap_link's pll_init() copies it (PLL_LOCKCNT 0x1000, IDLE with SIC_IWR0 = 1) plus TWI PRESCALE 12. Result: clean YUYV, one byte per sample, line period 1560 samples (0..1279 active, 640 px), 480 lines. The PLL raises the Blackfin to ~0.17 A at 3.0 V.
- [2026-11-12] [MD_CAM/FACTORY_PPI]: The factory program (disassembled from L1) sets PPI_CONTROL 0x3E0D, PPI_COUNT 1279, PPI_FRAME 480, PORTF_FER 0x03FF/MUX 0x0055, PORTG_FER 0x7C60/MUX 0x0480, DMEM_CONTROL 0x101B, waits for VSYNC in software on PG7 (GPIO) and DMAs 640x480 16-bit to SDRAM 0x00100000; it also compresses to JPEG itself.
- [2026-11-14] [MD_CAM/PPI_CONTINUOUS]: With PG5..PG7 in function 2 HREF/VSYNC never reach the PPI as frame syncs, and function 1 gives no capture at all. What works: wait for VSYNC in software on PG7, then run the PPI without frame syncs (PPI_CONTROL 0x383D: XFR_TYPE 11, PORT_CFG 11, DLEN 16, no SKIP) as one continuous stream; lines start at exact multiples of the line period from the PPI start.
- [2026-11-16] [MD_CAM/FRAME_SDRAM]: snap_link captures a whole frame with one DMA (PPI -> SDRAM 0x00300000, 49 x 15360 samples = 1.5 MB, XMOD/YMOD 2) and picks lines from there (falls back to L1 bands if the DMA does not complete); 0xFF800070 = PPI_STATUS<<16 | DMA0_STAT.
- [2026-11-14] [MD_CAM/SDRAM_HIRES]: External SDRAM works only after an init like the factory's (EBIU_SDGCTL 0, pause, SDRRC 0x26B, SDBCTL 0x11, SDGCTL 0xC0911109, dummy read of address 0; needs SCLK 120 MHz). Transmit buffer in SDRAM 0x00100000 (max 0xFFF0 bytes, 16-bit length). 0xD2 = 640x480 colour JPEG; the gateway (MAX_IMAGE_SIZE 64 KB) serves the last wide picture on /api/camera_large.jpg.
- [2026-11-14] [MD_CAM/STANDALONE_OK]: sensor_init() replays the factory's own sequence (soft reset 0x0103 = 1 and 108 writes, logged with a JTAG hardware breakpoint on the factory TWI write routine; saved in blackfin/build/ov7955_factory_init.txt). The factory writes image processing (0x5000, gamma 0x5301.., colour matrix 0x5601..) only there; at runtime only exposure/gain (0x3501/02, 0x350A/0B, 0x3503), AEC limits (0x3A02/03/26/27) and VTS (0x380E/0F).
- [2026-11-14] [MD_CAM/OV7955_AEC]: Leave 0x3503 = 0x00 (sensor AEC/AGC on) after init; skipping it gave overexposure. With AEC running, parts captured at different times may differ slightly in brightness.
- [2026-11-15] [MD_CAM/KEEP_ON_AEC]: After a cold start the first picture is ~12 levels brighter than a minute later, so aec_settle() captures the middle strip until the mean is within 1 of the value 10 captures earlier (max 75, ~0.2 s each; status 0xFF800068). Comparing adjacent captures was not enough.
- [2026-11-16] [MD_CAM/COLOUR_DRIFT]: After a cold start the sensor's colour drifts (Cb +4..5 for a few s); 0x3406 = 1 (manual AWB on OV5640-like sensors) does nothing on the OV7955. snap_link chroma_track() corrects awb_du/dv from MCUs where Y has not changed and re-extracts from the same frame; first delta after cold start -> 0 blocks. Grey-world AWB (AWB_OK 2026-11-15) sets the base offsets.
- [2026-11-16] [MD_CAM/IMAGE_QUALITY_SW]: 320 picture = mean of 2x2 sensor pixels from 10-bit samples (no +8 rounding: it saturated blocks to black), radial lens correction (SHADE_K 127), saturation U/V x7/4, JPEG quality 65, sharpening (SHARP_Q 4) only at JPEG encoding so REF stays unsharpened. Deltas use the base picture's quality. JTAG tuning words: see snap_link.c. The picture is now limited by lens blur.
- [2026-11-14] [MD_CAM/JPEG]: The Blackfin encodes JPEG itself (jpeg_enc.c, colour 4:2:0, DRI = one block row); snap_link answers 0x5A when done (the CC1110 polls meanwhile), the read gives length (2 bytes LE) + JPEG. gdbproxy cannot "dump binary memory" (packet error): read with x/NNNxw. JPEGs with missing chunks keep all markers, but strict PIL refuses them (use LOAD_TRUNCATED_IMAGES).
- [2026-11-14] [MD_CAM/DELTA]: Command 0xD3 compares each 8x8 block (Y and Cb/Cr) against the SDRAM reference (mean |difference| > DELTA_T) and sends only changed 16x16 MCUs ("D1" + id + count + entries); a full picture (RST after each MCU, COM "I" + id) when the reference is missing, after 120 deltas or when >50 % changed. The gateway (jpeg_splice.cpp, host-testable) splices MCUs into the base without decoding. AC dead zone 0.6.
- [2026-11-16] [MD_CAM/DELTA_NOISE]: Delta noise floor (histogram at 0xFF800080..0xFF8000FC) is 4-7 in a static room, max ~10, and comes from Y (probably lamp flicker), not U/V. DELTA_T 12 gives 0 false blocks and catches real change; DELTA_T 6 turned static dark scenes into full pictures.
- [2026-11-15] [MD_CAM/DELTA_HYSTERESIS]: Neighbours of a changed block are sent at half the threshold (one step out) so moving edges do not stay from the reference as squares. Large close-up movements exceed 50 % and become full pictures.
- [2026-11-15] [MD_CAM/DELTA_OK]: Open issue: in an alarm the picture after the 640x480 one sometimes became a full picture (id 2) instead of a delta (2 of 3 times); not investigated: read 0xFF800054 (changed MCUs) to see whether more than half counted as changed.
- [2026-11-16] [MD_CAM/FLASH_PICTURE]: 0xD4 = grayscale 320x240 IR flash picture (aec_settle, then PF10+PF12 for 5 ms from the frame start); no delta reference, the gateway keeps the colour picture as base when a JPEG lacks a COM id. 0xD5/0xD6 (BF_AUTO_FLASH) take D4 if the scene mean < DARK_Y 40, otherwise D3/D2. Colour under IR flash gave strong casts, hence grayscale. /api/camera.jpg keeps the colour picture; the flash picture only goes to MQTT. Real PIR motion in darkness not yet tested.
- [2026-11-16] [MD_CAM/FLASH_ROOM]: The IR flash only matters in a completely dark room: with ambient light the AEC keeps exposure short and the diodes do not reach 1-4 m (no measurable effect). Beware other IR-lit cameras in the room (a "dark" Y 81 was lit by one; truly dark is Y 4-5).
- [2026-11-23] [MD_CAM/NIGHT_VTS]: Bench-tested OV7955 long exposure over JTAG (0xFF800034) in a dark room. Auto-AEC ignored raised VTS/AEC limits (0x380E/0x3A02/0x3A26=0x08). Manual exposure (0x3503=0x01, VTS 0x380E=0x10 = 4109 lines, 0x3501=0xFF ~8x) lifted dim stray-light scenes (mean Y 12.6 -> 54.2), but in true darkness (no external IR) stayed nearly black (mean Y 4.28 -> 6.60) vs IR flash D4 (mean Y 141.8). Auto-IR flash (D5/D6 -> D4 below DARK_Y 40) remains the right night solution; no VTS firmware change needed.
- [2026-11-13] [MD_CAM/RF_IMAGE_OK]: Superseded raw-tile link (0x81 chunks, ~150 B/s, ~8.5 min per picture) by JPEG over 0x82 packets; lesson kept: per-packet MQTT publishing on the gateway was the bottleneck, so assemble pictures in the gateway and publish once.
