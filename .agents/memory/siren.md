# Memory: Siren (MSP430F149, CC1101, OKI L22901-707)

## 🔊 Siren (MSP430F149, CC1101, OKI L22901-707)
- [2026-11-25] [SIREN/IC2_OKI_L22901]: Bench-verified IC2 (`OKI L22901-707`) parallel audio interface on `P6.0..P6.5` (IC2 pins `13..18`), `P1.4` (TP2, active-LOW audio/op-amp rail), and `P1.7` (IC9 HV horn boost, active-HIGH; keep `INPUT` Hi-Z on bench with Saleae Logic 4 unless `SIREN_ENABLE_HV_BOOST` is defined). `P6.4` (pin 17, TP38) is falling-edge `STARTB`/`STB` (drive bits with `P6.4 = 1` for 10 ms setup, then `P6.4 = 0` to latch); `P6.0` (pin 13) is `STOP`/power-down (`val5 = 0x01`, ~55 ms ramp-down to sleep); `P6.1` (pin 14) must be `0` (`1` = no-op); `(P6.5, P6.3, P6.2)` (pins `18, 16, 15`) select sound `1..7` via `P6OUT = ((val5 & 0x10U) << 1) | (val5 & 0x0FU)`: `0x04` (2-beep ~440 ms), `0x08` (~2112 Hz decaying tone ~560 ms), `0x0C` (2-tone chime 1122->1046 Hz ~650 ms), `0x10` (powered idle/silence >2.5 s, +1.1 mA), `0x14` (full-amplitude alarm siren burst ~2.15 s, re-trigger every 2 s), `0x18` (ding-dong 2007->1514 Hz ~1.8 s), `0x1C` (1-beep ~200 ms).
- [2026-11-25] [SIREN/P1_7_HI_Z_LPM3]: Bench Otii Arc measurement showed driving `P1.7` (`IC9` boost enable) as `OUTPUT LOW` continuously sinks `12.05 mA` (`12.11 mA` total LPM3 idle). Leaving `P1.7` as `INPUT` (Hi-Z, `P1DIR` bit 7 = `0`) keeps `IC9` OFF and drops LPM3 idle current to `7.6 uA` (matching factory `6.66 uA`). Keep `P1.7` Hi-Z `INPUT` in `hal_msp430.c` (`gpio_init_safe()`) and `siren_audio_set()` unless `SIREN_ENABLE_HV_BOOST` is defined.
- [2026-11-25] [SIREN/TH1_SHT0_4]: Keep `SHT0_4` in `hal_read_th1_adc()` (`hal_msp430.c`): `encode_th1_temp()` is bench-calibrated to `SHT0_4` (~21.5 C at room temp); changing to `SHT0_8` saturates `TH1` to `85.0 C` on the `GW-SI` PCB at both `3.0 V` and `3.3 V`.
- [2026-11-25] [ARCH/MULTI_DEVICE]: Every feature (downlink slots, HA discovery, web portal controls, telemetry) must be per-deviceId so users can run multiple sirens, cameras, and sensors simultaneously; never hardcode single-device assumptions.
- [2026-11-25] [SIREN/WOR_FAST_WAKE]: Optional per-siren CC1101 Wake-on-Radio ("Fast Wake (Doorbell)") mode uses `869.525 MHz` (Band 54, 10% duty cycle), `SYNC=0x2DD4`, 24-bit FNV-1a per-siren `ADDR`+`tag16`, `EVENT0=0x876B` (1.0 s), and `P2.7`/`GDO2` `PORT2_VECTOR` IRQ. Wake packets only trigger a `TAR`-aligned authenticated `0xBA` poll on `868.950 MHz` (never direct audio). Gateway `radio_task.cpp` interleaves `14`-pkt TX slices (`46.7 ms`, arming `MCSM1=0x30` only once `TXBYTES < 6` so remaining FIFO packets are not truncated) with `24.5 ms` `868.950 MHz` RX slices (`rxExtendStartUs` anchored at frame start). Bench-verified on `2S5F554X` + `COM9` + Otii Arc: `0.937 s` `ding_dong` wake latency, `2.172 s` `ON->OFF` wake latency, `+13.8 uA` WOR overhead over `7.6 uA` `SPWD` LPM3 floor (`~21.4 uA` standalone WOR idle).
- [2026-11-25] [SIREN/HV_BOOST_HORN]: Bench-verified full-volume piezo horn (`CN2`) with `-DSIREN_ENABLE_HV_BOOST` at `3.0 V` (`1.5 A` OCP, Otii Arc 4 kHz) across all 6 tones (`beep`, `double_beep`, `chime`, `ding_dong`, `tone`, `alarm` 4 s): peak `110.8–133.8 mA` (`alarm` mean `81.04 mA`), zero brownout (`2946–2949 mV`), and `P1.7` returns cleanly to Hi-Z `INPUT` (`66.6 uA` p50 with BSL wires still attached, zero `12 mA` leak). `-DSIREN_ENABLE_HV_BOOST` is enabled by default in `env:siren_f149` (and `siren_f149_ci`); use `env:siren_f149_bench` to build without HV boost when probing with a logic analyzer.
